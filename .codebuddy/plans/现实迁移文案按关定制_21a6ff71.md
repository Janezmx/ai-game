## 产品概述

在「清醒边界」的复盘报告中，把收尾节「把练习带回现实」从"5 关共用同一份文案"改为"按关卡定制"，让玩家刚打完的那一关（煤气灯/职场PUA/亲情绑架/网络攻击/隐性歧视）得到与该主题直接对应的现实校准。

## 核心功能

- **按关定制引言**：每关一段专属开场（如第 1 关"这一关练的是记忆被否认。现实里，人是真的会记不清。"）。
- **新增「本关最容易被误读成操控的」**：每关一条对照，说明该关最典型的正常情境与操控的区别判据（如第 3 关"'我希望你回来'可能是绑架，也可能只是想念——区别在于你说'不'之后他是否接受"）。
- **三个自检问题按关定制**：每关一套专属的三问，但必须落在同一三段式骨架上——① 模式性（一贯 vs 这一次）② 表达与选择权（针对事 vs 针对人）③ 表态后的反应（给标准/共同核对 vs 继续否定）。总数恒为 3 条。
- **跨关保持不变**：标题「🌱 把练习带回现实」、栏目名「🧭 三个问题，帮你分辨」、两种结果分支（三个都是「否」/「是」）、收尾两句。因下方分支文案依赖"三个"这一数量，任何关卡都不得增删问题条目。
- **两个出口逐字一致**：复盘页面与导出的 Markdown 报告都从同一份按关数据取值，不允许各自硬编码。
- **文档同步**：设计文档中该节的通用版文案改为按关版，口径与代码逐字一致。

## 视觉呈现

复盘卡片结构保持不变，仅在引言之后多出一行「⚠️ 本关最容易被误读成操控的」标签与一段说明正文（字号与正文一致、颜色略深、左侧 peach 竖条与"三个问题"区分层级），随后是按关的三个编号问题，之后仍是共用的结果分支与收尾句。5 关看下来文案各不相同，但版式、层级与节奏完全一致。

## 技术栈

沿用现状，不引入任何新技术与依赖：

- 表现层：React Native Web（`react-native` + `react-native-web`）+ TypeScript，Vite 构建
- 文案数据层：纯 TS 常量模块（无框架依赖）
- 校验：本地 `tsc --noEmit`（Windows 下直接调用 `node node_modules/typescript/bin/tsc`，避开 npm 包装脚本噪声）

## 实现方案

### 总体策略

把 `frontend/src/utils/realityTransfer.ts` 从"全局一份常量"升级为"**按关取值 + 钳位兜底**的数据模块"，消费端（复盘页、导出报告）改为传入关卡号取值。这是纯展示层改造：不动后端、不动模型、不动四维评分与存档结构。

沿用项目既有同构写法（`KnowledgeCard.tsx` 的 `getLevelKnowledgePoint`）：

```ts
return LEVEL_KNOWLEDGE[Math.min(5, Math.max(1, level))] || LEVEL_KNOWLEDGE[1];
```

新模块采用完全相同的"钳位 + 回退第 1 关"模式，越界（0 / 6 / undefined）不抛异常。

### 关键决策

1. **按关数据用 Record 映射而非函数内 switch**：与 `LEVEL_KNOWLEDGE` / `LEVELS` 的组织方式一致，便于逐关校对文案，也便于后续扩关。
2. **引言从 string[] 收敛为单条 string**：原 `REALITY_TRANSFER_LEAD` 是数组但恒为 1 条（数组形态是为将来加段落预留的，实际未被使用）。按关版直接给单条，消费端少一层 `.map`，避免"数组里塞多段"这种隐性复杂度。
3. **保留跨关共用常量，而不是把整节都按关拆开**：结果分支文案依赖"三个"这一数量，且"边界不是对所有人都设防"是全局收尾锚点。拆开会同时破坏数量耦合与记忆锚点。
4. **"最易误读"文案入库前逐一校验结构骨架**：三段式槽位不可错位（①模式性 ②表达权 ③表态后反应），这是对"问题按关定制后丧失可迁移性"的唯一对冲。定稿的 15 条已按骨架写就，实施时只允许微调措辞。
5. **不删除已确认无引用的旧导出**：`REALITY_TRANSFER_LEAD` / `REALITY_CHECKS` 的引用点已核实**仅**存在于 `ReviewScreen.tsx` 与 `reportExport.ts` 两处，无其它消费方、无测试引用，可安全移除；移除时同步清理两端的 import，避免遗留未使用导入触发 lint。

### 性能与可靠性

- 纯对象查表 + 算术钳位，O(1)，无 I/O、无网络、无额外渲染；不引入新的组件层级或状态，因此不改变复盘页的渲染次数。
- 单一数据来源保证页面与导出逐字一致；钳位函数保证脏关卡号（旧存档缺 `level`、越界值）不影响页面可用性。
- 视觉层级只增一个样式，不改动既有 `realityCard` 结构；注意现有 `styles.realityText` **不带 `flex`**，行内条目必须继续用带 `flex: 1` 的 `styles.realityCheckText`，避免出现文字不换行/挤压。

## 关键代码结构

以下是多方依赖的核心类型契约（仅接口层，不含实现）：

```ts
/** 单个关卡的现实迁移文案（引言 + 最易误读 + 三个问题） */
export interface RealityTransferCopy {
  /** 本关引言：一句话点出本关练的是什么，并给出该主题在现实中的常态 */
  lead: string;
  /** 本关最容易被误读成操控的情境，以及区分它与操控的判据 */
  misread: string;
  /** 本关三个自检问题；长度恒为 3，且必须依次落在"模式性 / 表达与选择权 / 表态后的反应"三个槽位上 */
  checks: string[];
}

/** 按关卡取本关现实迁移文案；level 越界（0/6/undefined）时钳位到 1-5 并回退第 1 关 */
export function getRealityTransfer(level: number): RealityTransferCopy;
```
