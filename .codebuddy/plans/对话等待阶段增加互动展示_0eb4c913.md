## 产品概述

在《清醒边界》游戏中，玩家发送消息后等待 AI 回复（NPC 生成结构化评估）耗时较长，当前等待阶段仅有单调的三点跳动动画。本次需求是在「对话等待回复」阶段（`isWaiting === true`，即玩家发送消息后到 NPC 回复 `done` 事件到达前）加入有意义的互动展示，让等待过程不再枯燥，同时传递心理学教育价值。

## 核心功能

- **等待互动面板**：玩家发送消息进入等待状态时，在对话区显示一个轻量互动面板，等待结束后自动消失。
- **科普卡片轮播**：展示本关操控手法相关的心理学知识点，内容取自本关 `knowledgePoint`（`definition`、`signals` 识别信号等），在等待期间定时循环切换。
- **正念短句轮换**：穿插展示边界守护相关的暖心文案/正念短句，与科普卡片交替出现，缓解等待焦虑。
- **平滑过渡动画**：内容切换时带淡入淡出效果，提升视觉质感。

## 视觉与交互

- 面板不遮挡历史对话，位于等待中的 NPC 空气泡附近或对话区上方。
- 等待结束（`done`/`error` 事件）后面板立即消失，不打断正常对话流程。
- 内容每数秒自动切换，科普卡片与正念短句交替轮播。

## 技术栈

- 前端框架：React Native（现有项目技术栈）
- 样式：`StyleSheet`（复用现有 `theme.ts` 的 `palette`/`radius`/`space`/`fontSize`/`fontFamily` 设计令牌）
- 动画：`Animated`（已在 BattleScreen 中导入并使用）
- 状态管理：`zustand`（复用现有 `useGameStore`）
- 数据来源：`KnowledgeCard.tsx` 的 `getLevelKnowledgePoint` / `LEVEL_KNOWLEDGE` 静态知识点，及 `store.currentKnowledgePoint`

## 实现方案

### 整体策略

在 `BattleScreen.tsx` 中新增一个独立的 `WaitingInteractionPanel` 函数组件，基于 `isWaiting` 状态控制显示/隐藏。组件内部维护轮播索引与淡入淡出动画，从本关 `knowledgePoint` 提取科普内容，配合本地正念短句常量数组，实现等待期的定时循环展示。

### 关键设计决策

1. **独立子组件封装**：将等待互动的展示逻辑封装为 `WaitingInteractionPanel`，与主组件解耦，避免 `BattleScreen` 进一步膨胀。通过 props 传入 `knowledgePoint` 和 `visible`，由父组件控制生命周期。
2. **内容来源复用**：科普卡片复用现有 `knowledgePoint` 数据（`definition` + `signals`），不新增数据源；正念短句新增一个本地常量数组（模块级 `MINDFULNESS_QUOTES`），内容围绕「边界守护、自我价值、情绪稳定」主题，与游戏内核一致。
3. **定时轮播机制**：用 `useEffect` + `setInterval` 驱动索引自增，每约 3.5 秒切换一条内容；每次切换触发 `Animated` 淡出→更新内容→淡入的动画序列。`visible` 从 `true` 变 `false` 时清除定时器并立即隐藏。
4. **轻量无侵入**：面板作为覆盖在对话流中的临时元素，等待结束即卸载/隐藏，不影响现有 `LoadingDots`、输入框 placeholder 等逻辑；不改动 SSE 事件处理与胜负判定。

### 性能与可靠性

- 定时器在组件隐藏/卸载时清理（`useEffect` cleanup），避免内存泄漏与后台无效更新。
- 内容轮播为纯本地状态切换，无网络请求、无额外渲染开销。
- 动画使用 `useNativeDriver: true`（透明度动画），避免 JS 线程负担。
- 面板高度受限（`maxHeight`），不挤压聊天区布局。

### 关键代码结构

```
// 正念短句常量（模块级）
const MINDFULNESS_QUOTES: string[] = [
  "你的感受是真实的，不需要任何人来证明。",
  "边界不是墙，而是你与世界温柔的约定。",
  "你可以关心他人，同时坚定地守护自己。",
  "拒绝不等于冷漠，说「不」是你的权利。",
  "先稳住呼吸，再回应世界。",
];

// 等待互动面板组件
function WaitingInteractionPanel({
  visible,
  knowledgePoint,
}: {
  visible: boolean;
  knowledgePoint: KnowledgePoint | null;
}) {
  const [index, setIndex] = useState(0);
  const opacity = useRef(new Animated.Value(0)).current;
  // 由科普条目 + 正念短句构成轮播序列
  const items = useMemo(() => {
    const knowledgeItems = knowledgePoint
      ? [
          { type: "definition", text: knowledgePoint.definition },
          ...knowledgePoint.signals.map((s) => ({ type: "signal", text: s })),
        ]
      : [];
    const quoteItems = MINDFULNESS_QUOTES.map((q) => ({ type: "quote", text: q }));
    return [...knowledgeItems, ...quoteItems];
  }, [knowledgePoint]);
  // 可见时启动轮播定时器 + 淡入淡出；不可见时清理
  // 渲染：科普卡片（含 📖 知识点标签）与正念短句（含 ✨/🌿 标签）交替展示
}
```

### 渲染入口位置

在 `BattleScreen` 的对话 `ScrollView` 附近（`loadingContainer` 之后、消息列表之前，或作为覆盖层）插入：

```
<WaitingInteractionPanel
  visible={isWaiting && conversation.messages.length > 0 && !battleEnded}
  knowledgePoint={knowledgePoint}
/>
```

确保仅在「玩家已发消息、正在等 NPC 回复」时显示，NPC 生成阶段（`isNPCGenerating`）不触发。

## 实现注意事项

- **避免遮挡**：面板应放在消息区上方或作为轻量横幅，不影响用户回顾历史对话；若放在 ScrollView 内，注意滚动位置。
- **生命周期**：`visible` 变 false 时立即停止定时器并隐藏，避免 `done` 事件后残留。
- **复用主题令牌**：颜色、圆角、字号均从 `theme.ts` 引入，保持视觉一致性，不硬编码。
- **不改变胜负/回合逻辑**：本改动纯前端展示层，不触碰 SSE 事件、`latestValues`、`victoryTriggered` 等核心状态。
- **日志**：不新增日志，复用现有行为（无 secrets/PII 风险）。
